信息架构IA CHANGES

  • 作品系列页 /collection：副文案改「每种时刻 · 各成一册」，双封面下方新增「更多时刻」三入口（订婚宴跟妆 / 孕妈照 / 亲子照）。
  • 新系列路由：/style/engagement /style/maternity /style/family，共用现有 styleList 模板（中性 ms 主题、圆角矩形封面、卡上带热度行）。
  • 新系列相册详情：/album/:slug 按 album.layout=flat 渲染瀑布流视图——矮 hero + 热度条 + 2 列错落图墙 + 悬浮互动 dock。
  • 婚礼跟妆（western / chinese）完全不动：六段叙事、secmark、暗房、双封面全部保持。
  • 命名口径：孕妈照（不叫孕妇照）、亲子照，作品系列即分成两个独立入口。

数据模型DATA MODEL

  • 新表 album_stats：album_id PK · views · likes · shares · updated_at。与 album 1:1，计数不进主表（热度可单独缓存/重置）。
  • collection 表加 3 行：engagement / maternity / family（cover_key、tagline 等填新文案，双封面专用字段可空）。
  • album 表加 layout 列（sectioned | flat，默认 sectioned）——显式字段而非按系列名推断，配置驱动。
  • seed：订婚宴 2 册 / 孕妈 2 册 / 亲子 2 册，复用现有 demo 图片资产，无 sections 数据。
  • 公开接口 GET /api/albums* 响应内嵌 stats 三计数（含列表页）。

接口与互动口径API & INTERACTION

  • POST /api/albums/:slug/stats，body {type:"view"|"like"|"share"}，服务端原子 +1，返回最新三计数。
  • 浏览量：进入详情页即上报（前端 sessionStorage 按 slug 防同会话重复刷，同会话多次进入只计 1）。
  • 点赞：localStorage 记录已赞 slug（demo 无账号体系）；已赞再点 = 取消并 -1；红心点亮 + 微弹 + 「+1」气泡。
  • 分享（转发）：优先 navigator.share；微信内置浏览器降级为玻璃面板（复制链接 / 提示截图分享），复制或系统分享成功回调后计 1。
  • 热度行在列表卡、详情热度条两处外露；后台 M6 可看全量并可清零。

待你拍板OPEN QUESTIONS

  • ① 双封面下方三入口的形态：本稿用「玻璃横卡列」，也可以做成小封面双列卡（更图墙感）。
  • ② 瀑布流详情的hero 高度：本稿 250px 矮 hero（进图快），也可以做无 hero 直接图墙。
  • ③ 点赞能否取消：本稿口径可点第二次取消 -1；若要「只能赞不能取消」请明示。
  • ④ 浏览量防刷口径：同会话只计 1（本稿）；要不要按 24h 去重（需多一张记录表或 Redis，demo 阶段建议先 session）。
  • ⑤ 中式尾部「下一册」是否同步改「新中式 NO.2」格式（上轮遗留问题）。
确认设计后动工顺序建议：数据模型迁移 → stats 接口 → 三个新系列 seed → 瀑布流详情视图 → 系列页 1+3 → 互动 dock/分享面板 → 双端回归。
